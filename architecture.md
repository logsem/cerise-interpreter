# Architecture

The `src/` tree contains the CLI, session-oriented application model, and Notty terminal UI.
`lib/` contains the installable library: `core/` provides backend-neutral assembly construction,
diagnostics, codecs, and machine interfaces, while each `lib/<backend>/` directory owns one
backend's AST, assembler IR, generated lexer/parser composition, printer, codec, and machine.

The top-level `lib/vanilla.ml`, `locality_cerise.ml`, `ucerise.ml`, `mcerise.ml`, `cerisier.ml`,
`griotte.ml`, and `griotte_extracted.ml` files are sealed public façades. `Ast` is the semantic
machine representation; `Asm_ir` is the backend-owned syntax representation lowered into it.
Shared token and construction fragments live in `lib/assembly/` and are composed by Menhir
with each backend grammar. Expressions, labels, definitions, and typed macros are implemented by
`Assembly_construction`; exact instruction syntax remains backend-owned.

`Machine_session` owns persistent execution and edits, and `Machine_view` is the pure rendering
snapshot boundary. Terminal/Notty code is source-only and does not enter the library API. Codec
tables are backend-owned and provide the exact ISA encodings.

`Griotte_extracted` contains generated Rocq output plus a handwritten adapter. Generated bytes are
trusted only at the checked-in regeneration boundary: use `make regenerate-griotte-extracted` or
the wrapper `scripts/regeneration-gate.sh`, which delegates to
`lib/griotte_extracted/scripts/` and verifies byte identity and provenance.
